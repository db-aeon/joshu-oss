# Release notes: 0.1.47 → 0.1.59 (OSS)

Git tag: `v0.1.59-oss`

| Image | Ref |
|-------|-----|
| Sandbox | `ghcr.io/db-aeon/joshu-oss:0.1.59` |
| Voice (optional `voice-rt` profile) | `ghcr.io/db-aeon/joshu-oss-voice-realtime:0.1.59` |
| Instance agent (optional `fleet` profile, new) | `ghcr.io/db-aeon/joshu-oss-instance-agent:0.1.59` |

Pin: [`deploy/RELEASE.json`](../../deploy/RELEASE.json) · Example env: [`deploy/.env.vps.example`](../../deploy/.env.vps.example)

Hermes (`3c27eb6`) and gbrain (`fa2c7a6`) are unchanged. Postgres for Hindsight is still version 17.

Plain-language summary: section [User summary](#user-summary) at the end of this file.

0.1.59 is the first open-source release since 0.1.47, so these notes cover the work of twelve releases. Three changes affect how you run a box:

- The release images are now the only code on a box. Compose no longer mounts code from a git clone on the host.
- Camofox and noVNC are gone. The shared browser is local Chromium or Browser Use Cloud, and the sandbox image is about 3.5 GB smaller.
- The Joshu state (teams, proactive state, browser handoffs, SMS sessions, metered provider keys) moves into the volume `joshu_arozos`, so it survives a recreate of the stack container.

Read [Upgrade notes](#upgrade-notes-from-0147) before you upgrade a box.

## What changed since 0.1.47

### Box runtime and upgrades

The release images are the only source of code on a box. Until now, `deploy/docker-compose.yml` mounted many host paths from the git clone at `/opt/joshu` over the image (`dist/`, skills, `factory/`, templates, ArozOS overlays, `public/`, and more). A release did not replace those files, so a box could run old code next to a new image. Now compose mounts no host code into `joshu-stack`. The one exception is the hotfix overlay `/opt/joshu/hotfix/scripts/`, and each upgrade empties it.

The sandbox image now carries a small host bundle at `/opt/joshu/.image/host/`. The bundle has the compose file, the env example, the Caddy scripts, and the script `install-host-bundle.sh`, which writes the bundle to `/opt/joshu/deploy/`. `bootstrap-vps.sh` uses the bundle and no longer clones the repository for a fresh install. The compose file sets the project name `deploy`, so the volume names stay `deploy_joshu_*` and `deploy_caddy_*`.

Other changes to the box runtime:

- The instance agent runs from its own image (`joshu-oss-instance-agent`). It no longer uses `git pull` or builds itself on the host. You need it only if you run the `fleet` profile with your own control plane.
- The Joshu API keeps its state in `JOSHU_STATE_DIR`, which the image sets to `/var/lib/arozos/joshu-state` in the volume `joshu_arozos`. Earlier releases kept the state in `/opt/joshu/.joshu` in the writable layer of the container, so each recreate lost it. The new script `deploy/scripts/carry-over-joshu-state.sh` copies the old state into the volume. It never overwrites state that is already there.
- The new script `deploy/scripts/prune-release-images.sh` removes old release images after an upgrade. It keeps the current release, the newest other image for a rollback, and each image that a container uses. `DRY_RUN=1` lists what it would remove, and `JOSHU_PRUNE_RELEASE_IMAGES=0` turns it off.
- The Joshu API installs the box cron jobs "Joshu onboarding reconcile", "Joshu proactive tick", and "Joshu proactive hygiene" at each start. Before, only Finish setup installed them, so a box could miss them.
- The start period of the stack healthcheck goes from 180 to 600 seconds, because the first start of a release can run the skills seed for several minutes.
- A start or stop script stops a PID from a PID file only when that PID runs the expected command. Before, a stale PID file on a persistent volume could make the gbrain stop script kill Hindsight.
- `scripts/start-hindsight.sh` copies the Google reranker key to `/run/joshu-hindsight/` at each start and gives the copy to the Hindsight user. `install-host-bundle.sh` and `bootstrap-vps.sh` set `/etc/joshu` to mode 711, so service users can reach `/etc/joshu/secrets`.
- The system `python3` in the image has `requests` again, so scripts that the companion writes with `import requests` still work after the move to `debian:trixie-slim`.

### Hermes gateway, cron jobs, and skills

- Cron jobs and chat turns no longer stop at "starting API call". The Joshu API never read the stdout pipe of the Hermes gateway, and the Langfuse relay plugin printed a line for each LLM call, so after about 240 calls the pipe was full and the gateway blocked. The Joshu API now reads both pipes, and the relay plugin logs through Python `logging`.
- A model switch no longer makes Hermes skip cron jobs. Hermes skips an unpinned cron job when its creation model differs from `model.default`. Joshu now sets `cron.model` and `cron.model_provider` in the Hermes config, so unpinned jobs follow the default model.
- A new owner timezone applies to the running gateway. When the owner timezone changes, the Joshu API realigns the cron jobs and restarts the Hermes gateway. The API server is unavailable for about 45 seconds after the owner saves a new timezone.
- The skills seed now uses a content hash of all factory skills as its key, so each factory skill change reaches the box. A box skill with no box changes is replaced. A box skill with box changes gets an LLM merge, and the merge keeps each box pitfall unless the factory skill makes it wrong. Only one skills seed runs at a time (`JOSHU_HERMES_SKILLS_SEED_LOCK_WAIT_SEC`, default 1200 seconds).
- Release facts check old box notes. `factory/release-facts.yaml` lists facts that a release made true. After the skills seed, a one-time Hermes cron job reads `MEMORY.md`, `USER.md`, and the box skills, and it removes or rewrites what the facts make untrue.
- The background skill review can patch factory skills again. The Hermes patch for it never worked, because the inserted code used `os` without an import.
- Scratch files stay off the owner Desktop. HERMES.md tells the companion and each worker to write scripts and output under `/tmp/joshu-scratch/` and to delete them after use. `HERMES_WRITE_SAFE_ROOT` now defaults to the owner Desktop and `/tmp/joshu-scratch`, and the gateway starts with `PYTHONDONTWRITEBYTECODE=1`.

### Multiplayer teams

The companions of different owners can now work together in a team. The feature first shipped as "Boss Mode" and is now called Multiplayer.

- Any owner creates a team in chat, and that box becomes the team boss, which hosts the team room. Other boxes join with a single-use invite link. Nothing changes on a box until its owner creates or joins a team. See [teams.md](../teams.md).
- Each box runs a team stand-up. The stand-up is a Hermes cron job with a limited toolset and no memory. It reads the team room, posts what helps a team member, records team commitments on the team board, and tells the owner what helps the owner. The stand-up never gets every MCP server, so it cannot send mail.
- A wake check runs every 15 minutes without a model call (`JOSHU_TEAM_WAKE_MINUTES`, `0` turns it off). It starts the stand-up early when another member names the companion with "@", answers a message of the box, or changes a team card of the box.
- A text to the owner over the limit of 3 texts waits for the next workday instead of being lost.
- The stand-up finds its team folder and the blocked tasks of the team boards (new MCP tool `team_blockers`).
- The Multiplayer desktop app shows the last day of the team as a group chat. Each message shows the picture and name of the companion, and the team cards that the message names show inside it. The owner can reply, answer a question, approve a draft with "OK, send it", read earlier days, and edit the team notes. The board, the card details, and the member list stay next to the chat.
- Internal ids keep the name `boss-mode`, so nothing moves on disk.

### Slack chat

The owner can connect Slack with a sign-in and one Allow click.

- The owner clicks Connect Slack in the Safety app and signs in to Slack in jWeb. Joshu creates the Slack app of the box from a manifest, gets the tokens, and takes the OAuth redirect at `/joshu/api/slack/oauth/callback`. No token reaches a model, a trace, or a log.
- Joshu finds the Slack user of the owner from the Allow click, from the owner email, or from a pairing code. The owner no longer copies a member ID.
- The companion sends the first direct message after the gateway restarts with the new tokens. Hermes replies in the direct message, not in a thread, and Slack gets no "Gateway shutting down" notice.
- The sign-in step reads each tab of the shared browser, tells the owner what the box sees, and checks each click of the token steps.
- The manual path still works. The Safety app checks the tokens with Slack before it saves them.

See [slack-chat.md](../technical-reference/slack-chat.md).

### Shared browser

- Camofox and noVNC are removed. The image builds `FROM debian:trixie-slim`, and `vps-start.sh` starts local Chromium or Browser Use Cloud. The Hermes env no longer has `CAMOFOX_*` keys, and the dotenv sync removes them from `~/.hermes/.env`. Some names on the local Chromium path still contain "camofox" (for example `CAMOFOX_URL`).
- A sign-in popup (Google, Microsoft, GitHub, Apple) opens as a real popup, so "Sign in with Google" works on sites that use a popup. Other `window.open` calls still load in the same tab.
- On Browser Use Cloud, the live view follows a sign-in popup and goes back to the opener when the popup closes.
- jWeb shows the tab strip, the back and forward buttons, and the address bar of the Browser Use live view, so the owner sees every tab. The phone handoff page keeps the simple view.
- A checkout survives long waits. An unopened browser handoff holds the shared browser until the link expires, instead of 10 minutes. An SMS turn runs at least 5 minutes and up to 20 minutes while Hermes reports progress, and a stopped SMS turn continues as a background task.
- A page dialog no longer crashes the Joshu API. One dialog listener accepts a `beforeunload` prompt and dismisses other dialogs.

### Voice and phone

- Calls sound cleaner. The 24 kHz to 8 kHz phone downlink now filters before it drops samples, which removes the harsh, metallic sound. It adds about 4 ms of delay.
- On a box with no owner mobile, after the call gate unlocks an inbound call, the voice agent offers one time to save the caller ID as the owner mobile. It saves the number only on a clear yes.
- A new guard notices when the voice agent says it is working but no tool call ran, for example after the owner interrupts. The agent then gets a note and one more turn, so it does not say "still looking" with no work behind it.

### SMS, reminders, and nudges

- Owner reminders reach the owner. The companion makes reminders with the MCP tools `owner_reminder_create`, `owner_reminder_list`, and `owner_reminder_stop`. Each run sends fixed text by SMS, or by email from the companion mailbox when SMS fails, without an LLM call. Before, a reminder was a Hermes cron job whose output often went nowhere. The realtime goals plugin now blocks a new cron job whose delivery target cannot reach anyone.
- An SMS counts as delivered only with a Twilio delivery receipt. The owner outbox, reminders, nudges, team texts, and approval requests read the Twilio status. When the carrier rejects an SMS, Joshu tries email or fails the step, and an approval request stops at once instead of waiting 30 minutes.
- The companion can send email while the owner texts. Before, the Joshu API refused every companion email for 60 minutes after the last owner text. The action guard is now the only check.
- The SMS after a browser handoff gets the handoff as a system message, so the model no longer calls its own handoff a phishing attempt. The companion never asks the owner to text a secret, and SMS keeps line breaks, list items, and full links.
- Nudges ask the owner only real questions. The keyword rules and the clarify queue are gone. A blocked task counts as an owner question only when its block kind is `needs_input`.
- No nudge is written when the box has no route to the owner (no owner mobile and no email). A nudge by email gets no SMS reply prompts.

### Mail and tracks

- Workers can open Gmail attachments. The mail mirror lists each attachment, and the MCP tool `gmail_fetch_attachment` downloads one into `Projects/<project>/attachments/`, up to 25 MiB.
- Track lists are smaller. `mail_list_track_tasks` takes `threadId` and returns only the track of that thread. Without `threadId` it returns a compact list, and `taskId` returns one full track.
- A kept-blocked Kanban task now also gets a `blocked` event, so Hermes no longer moves it back to `ready` after 30 seconds.
- Each hour, the Joshu API archives an ingress task that is blocked for a reason other than `needs_input` and has had no event for 48 hours (`JOSHU_INGRESS_SWEEP_HOURS`, `0` turns it off).
- An owner reply from Gmail reaches the open tracks of its thread. Before, the Gmail sync skipped a thread when its newest message was a sent message.
- An owner reply-all that hands scheduling to the companion now goes to scheduling, instead of being filed as an owner note.
- The Gmail sync uses the `historyId` of the history listing as its cursor, removes the mirror of a deleted thread, and runs each connector cron job at most one time at a time.
- Mail triage writes no triage stub for mail older than 36 hours (`JOSHU_EA_SCHEDULING_MAX_AGE_HOURS`), so a catch-up of old mail does not fill the morning brief.
- Composio keeps one session per box in memory and makes a new one only on a 404, so parallel calls no longer create thousands of sessions.
- Skill `joshu-mail` tells a worker not to take a postal address from an email footer as a business address.

### Calendar

- The calendar event list works again after Composio made the Google Calendar toolkit strict. The MCP tool `google_calendar_list_events` loses its `limit` argument, which never had an effect.
- The Joshu API pins the Composio toolkits that it calls: Google Calendar `20261009_00` (override `JOSHU_COMPOSIO_GOOGLECALENDAR_VERSION`) and Slackbot `20261008_00` (override `JOSHU_COMPOSIO_SLACKBOT_TOOLKIT_VERSION`).
- Free slots and the event list read every enabled calendar account of the owner.
- New MCP tools `google_calendar_create_event`, `google_calendar_update_event`, and `google_calendar_get_event`. A write uses the calendar account that can write to the target calendar and goes through the action guard. The action guard now also asks the owner before `GOOGLECALENDAR_PATCH_EVENT`.
- A new event with guests and no location gets a Google Meet link by default.
- Create and update take `endTimezone`, so a flight can end in the arrival time zone.

### Memory and File Brain

- gbrain no longer pays for the same embeddings again and again. A sync that keeps failing backs off and pauses instead of escalating to a full sync. Before, every update to a page in a legacy `j-<user>` source failed after the embeddings were already paid for.
- One file that gbrain cannot parse no longer freezes the index, and a short failure such as a spending cap no longer hides files for good.
- The whole Desktop is one `default` source. Boot removes empty legacy `j-*` sources and clears a stale `.git/index.lock`.
- Renames no longer leave orphan pages, and boot prunes existing orphans (see the upgrade notes).
- Joshu page types (journal, inbox, connectors, planning) win over the gbrain type `note`, and the type filter of the File Brain viewer asks gbrain instead of filtering the latest 100 pages.
- File Brain no longer reindexes every 5 seconds. The gbrain MCP bridge ignores `.joshu/` folders and `.tmp` files, and the realtime goal broker writes `state.json` only when its content changes.

### Setup board

The setup board has 4 required steps (owner profile, owner mobile, at least one Gmail, at least one calendar), and each card has a how-to. 5 optional setup tips are blocked cards that get no nudge. While a required step is open, the companion ends one reply each day on each channel with a setup mention.

### Safety and privacy

- Each OpenRouter request that Joshu makes for an owner sets `provider.data_collection: "deny"`. The setting covers Hermes turns, cron jobs, workers, subagents, Hermes auxiliary tasks, Hindsight, the research engine, and the Joshu API. OpenRouter then does not route to a provider that may train on prompts. The setting excludes DeepSeek first-party.
- The Composio MCP guard now checks each inner tool call of `COMPOSIO_MULTI_EXECUTE_TOOL`, so a multi execute call cannot skip the hard blocks or the owner approval. The workbench runs on a second, read-only Composio session. Hermes always reaches Composio through the guard, also with the action guard off.
- Hermes approval prompts no longer offer Always. An "always" answer counts for the session only, and Hermes ignores existing `command_allowlist` entries.
- The terminal guard refuses pip installs into the Hermes venv, writes to the Joshu and Hermes program folders and to the Hermes config files, and changes to the Telephone settings. `execute_code` scripts go through the same check.
- HERMES.md section "Box problems" tells the companion to check read-only, report what it found, and never claim a fix it did not make.
- `GET` and `PUT /joshu/api/telephone` need an ArozOS desktop session or a direct localhost request. The responses no longer carry the passphrase. The Telephone app reads it with the new `POST /joshu/api/telephone/passphrase`.
- Each route under `/joshu/api/safety-settings` needs the ArozOS desktop session of the owner or a direct localhost request. Before, Caddy forwarded these routes with no check.
- `vps-start.sh` no longer exports the Slack and Telegram keys of `~/.hermes/.env`, so an old token there cannot win over a newer save in the Safety app. A key in `/etc/joshu/instance.env` still wins.

### Security updates of the images

- Node.js 22.23.4 (Brotli decoder remote code execution, TLS host name checks, removed eMudhra CAs).
- Hermes environment: Pillow 13.0.0, cryptography 50.0.2, PyJWT 2.15.1, brotlicffi 1.2.1.0, mcp 1.30.0, and PyNaCl 1.6.2. Hermes pins older versions, so the Dockerfile installs the fixed versions after Hermes, and the build checks them.
- Browser Use environment: Pillow 13.0.0, aiohttp 3.14.5, pypdf 6.21.2, anyio 4.14.2, and mcp 2.2.0.
- Joshu runtime: `@modelcontextprotocol/sdk` 1.32.2, `body-parser` 1.20.9 and 2.4.0, and OpenTelemetry 0.223. `npm audit --omit=dev` of `deploy/runtime` reports no critical or high finding.
- Desktop apps: CopilotKit 1.79.1 (fixes a critical `@a2ui/web_core` advisory) and DOMPurify 3.4.17.
- A full image build also takes Chromium 156 and Bun 1.4.4.

### Health

`/joshu/api/instance/health` has a new informational field `components.failures`. It lists Kanban runs that crashed, timed out, or gave up in the last 24 hours, and enabled cron jobs whose last run or delivery failed. It never changes `healthy`, and the result is cached for 10 minutes.

### Removed

- Camofox, noVNC, x11vnc, websockify, the `novnc` live view mode, and the noVNC client files. Compose loses no service or volume, because Camofox ran inside `joshu-stack`.
- The env keys `ENABLE_VNC`, `NOVNC_URL`, `NOVNC_PROXY_TARGET`, `NOVNC_CLIENT_PATH`, and `SESSION_TIMEOUT_MS`. No code reads them.
- `JOSHU_COMPOSIO_SLACK_TOOLKIT_VERSION`, with the unused module that read it.
- The `camofoxBase` pin in `deploy/RELEASE.json`.
- The host bind mounts of `deploy/docker-compose.yml`, except the hotfix overlay.
- The refusal of companion email while the owner texts (`nylas_send_blocked_sms_channel`).
- The proactive clarify queue and its keyword rules.
- Always in the Hermes approval prompts.

## Upgrade notes (from 0.1.47)

The upgrade changes the compose file, so do it by hand one time. The data volumes keep their names and their data. Postgres stays on version 17, so Hindsight needs no migration. To check, `docker run --rm --entrypoint cat -v deploy_joshu_postgres:/v ghcr.io/db-aeon/joshu-oss:0.1.59 /v/data/PG_VERSION` prints `17`.

First, check the compose project name. The new compose file sets `name: deploy`. If you always ran compose from `/opt/joshu/deploy`, your project is already `deploy`. `docker volume ls | grep joshu_postgres` must show `deploy_joshu_postgres`. If it shows another prefix, add `-p <that prefix>` to each `docker compose` command below, or compose creates new, empty volumes.

Second, set the release pins in `/etc/joshu/instance.env`:

```bash
sudo sed -i 's|^JOSHU_RELEASE_VERSION=.*|JOSHU_RELEASE_VERSION=0.1.59|' /etc/joshu/instance.env
sudo sed -i 's|^JOSHU_IMAGE_REF=.*|JOSHU_IMAGE_REF=ghcr.io/db-aeon/joshu-oss:0.1.59|' /etc/joshu/instance.env
sudo sed -i 's|^JOSHU_VOICE_IMAGE_REF=.*|JOSHU_VOICE_IMAGE_REF=ghcr.io/db-aeon/joshu-oss-voice-realtime:0.1.59|' /etc/joshu/instance.env
```

While you have the file open, you can delete `ENABLE_VNC`, `NOVNC_URL`, `NOVNC_PROXY_TARGET`, `NOVNC_CLIENT_PATH`, `SESSION_TIMEOUT_MS`, and `JOSHU_COMPOSIO_SLACK_TOOLKIT_VERSION`, because no code reads them. If `JOSHU_HERMES_MODEL` is still `deepseek/deepseek-v4-flash-0731` from an old example file, the example and the code default are now `deepseek/deepseek-v4.1-flash`. If you set `JOSHU_COMPOSIO_GOOGLECALENDAR_VERSION` by hand, it overrides the new pin `20261009_00`, so delete it unless you need it.

Third, pull the images and write the host bundle of 0.1.59 to `/opt/joshu/deploy/`:

```bash
docker pull ghcr.io/db-aeon/joshu-oss:0.1.59
docker pull ghcr.io/db-aeon/joshu-oss-voice-realtime:0.1.59

docker run --rm --entrypoint cat ghcr.io/db-aeon/joshu-oss:0.1.59 \
  /opt/joshu/.image/host/deploy/scripts/install-host-bundle.sh \
  | sudo JOSHU_IMAGE_REF=ghcr.io/db-aeon/joshu-oss:0.1.59 bash -s
```

The script keeps a copy of the old `deploy/` folder in `/opt/joshu/backups/deploy-<time>/`, writes the new compose file and scripts, empties `/opt/joshu/hotfix/scripts/`, records the release in `/opt/joshu/deploy/.host-bundle.json`, and sets `/etc/joshu` from mode 700 to 711. If `/opt/joshu` is a clone of joshu-oss, you can instead check out tag `v0.1.59-oss`, which has the same `deploy/` files. The rest of the clone is no longer used by the box.

Fourth, copy the Joshu state out of the running 0.1.47 container. Do this before you recreate `joshu-stack`, because the recreate throws away the writable layer that holds the state:

```bash
docker exec -i deploy-joshu-stack-1 sh -s < /opt/joshu/deploy/scripts/carry-over-joshu-state.sh
```

The script prints one line for each entry (`copied`, `kept`, or `failed`). `no /opt/joshu/.joshu` means that there is nothing to copy.

Fifth, recreate the services:

```bash
cd /opt/joshu/deploy
docker compose -f docker-compose.yml --env-file /etc/joshu/instance.env up -d --force-recreate caddy joshu-stack
docker compose -f docker-compose.yml --env-file /etc/joshu/instance.env --profile voice-rt up -d --force-recreate voice-realtime
```

You no longer need `sync-dist-from-image.sh`, because compose no longer mounts a host `dist/`.

If you run the instance agent (`fleet` profile), also set `JOSHU_INSTANCE_AGENT_IMAGE_REF=ghcr.io/db-aeon/joshu-oss-instance-agent:0.1.59` in `instance.env`, pull that image, and recreate `instance-agent` with `--profile fleet`. The agent now runs `node /app/dist/index.js` from its image.

Sixth, optionally remove old release images when the stack is healthy:

```bash
DRY_RUN=1 bash /opt/joshu/deploy/scripts/prune-release-images.sh
bash /opt/joshu/deploy/scripts/prune-release-images.sh
```

The script reads the current image refs from `/etc/joshu/instance.env`.

### What happens at the first start

The first start takes longer than usual. The healthcheck allows 600 seconds before it marks the stack unhealthy.

- Skills seed. The old seed stamp is not a content hash, so the skills seed runs one time. Each box skill that differs from its factory skill gets an LLM merge through OpenRouter. The log has `kept box pitfall` or `merge dropped box pitfall` lines.
- gbrain. `start-gbrain` removes empty legacy `j-*` sources and runs `gbrain-prune-orphans`. The prune is a soft delete that you can undo for 72 hours with `gbrain restore <slug>`, and it refuses to run when more than half of the pages would go. Check the stack log after the first start.
- Hermes config. `config.yaml` gets `cron.model` and `cron.model_provider`. Hermes points `mcp_servers.composio` at the Composio MCP guard. `HERMES_WRITE_SAFE_ROOT` in `/root/.hermes/.env` becomes the owner Desktop and `/tmp/joshu-scratch`, unless `JOSHU_HERMES_WRITE_SAFE_ROOT` sets it.
- Hermes patches. The approval patch removes Always, and Hermes logs that it ignores N `command_allowlist` entries on a box that has entries. The pairing reply patch and the OpenRouter `data_collection` patch are applied at build time and again at each start.
- Cron jobs. The Joshu API installs missing box cron jobs and adds the one-time job "Joshu release facts check 0.1.59". If the stored timezone of a cron job is wrong, the realign can make a recurring job run one extra time at the wrong hour.
- Composio. A saved Composio session gets one update that turns the workbench off, and the box makes a second, read-only session.
- Setup board. Boxes get the new required setup cards and the optional setup tips that apply.
- Telephone app. A Telephone tab that was open before the upgrade shows an empty passphrase on Show until you reload the tab.

### API changes that can affect your scripts

- `GET` and `PUT /joshu/api/telephone` and every route under `/joshu/api/safety-settings` return `401` from outside the box without an ArozOS desktop session. A direct localhost request still works.
- `GET /joshu/api/telephone` no longer returns `thinkPassword`. Use `POST /joshu/api/telephone/passphrase`.
- `google_calendar_list_events` has no `limit` argument, and the response adds `accounts[]` and `incomplete`.
- `mail_list_track_tasks` without `threadId` returns a compact list without bodies.

### Rollback

To go back to 0.1.47, set the pins in `instance.env` back to 0.1.47, copy the old compose file from `/opt/joshu/backups/deploy-<time>/` to `/opt/joshu/deploy/`, and recreate the services. 0.1.47 needs its host mounts, so the host clone must still have the 0.1.47 files. 0.1.47 reads the Joshu state from `/opt/joshu/.joshu` again, so the proactive state looks empty until you upgrade again. The volume keeps the copied state. The skills seed stamp of 0.1.59 is unknown to 0.1.47, so check the box skills after a rollback.

Fresh installs: [hetzner-quickstart.md](../vps-sandbox/hetzner-quickstart.md) (use tag `0.1.59`). `bootstrap-vps.sh` no longer clones the repository.

## Known issues

- The terminal guard checks the text of a command. A script that builds a path from parts can get past it.
- A few Composio tools have `readOnlyHint` by mistake, so the read session can reach them. The workbench can reach any internet host.
- The event details of a flight show both ends in the departure time zone, because Google labels both ends with one zone. The times on the calendar grid are correct.
- A Slack field that the owner clears in the Safety app stays in `~/.hermes/.env`.
- `filelock` stays on 3.32.7 in the Hermes environment, because the `litellm` version of Hindsight needs `filelock<4.0`. The advisories need another local account on the box.
- The root lockfile has 14 high findings from `zod` 3.25.76, which CopilotKit needs. The `zod` code runs only in the browser of the owner, on data from the box.

## User summary

Joshu OSS 0.1.59 in plain words, for the owner of a box:

- Your companion can work with the companions of other people in a team. The Multiplayer app shows the team as a group chat, and you can reply, answer, and approve drafts there.
- You can chat with your companion in Slack. Click Connect Slack in the Safety app, sign in, and click Allow.
- Joshu's browser shows all its tabs and the address bar, and "Sign in with Google" popups work.
- Reminders reach you by text, or by email when the text does not arrive. Joshu checks that a text was delivered.
- Your companion reads every calendar you connected, adds Meet links to meetings with guests, and puts flights on your calendar with the right arrival time.
- Workers can open email attachments, and your phone calls sound clearer.
- Your phone passphrase and your Safety settings can be read and changed only from your own Joshu desktop, and your companion can no longer get permanent approval for risky commands.
- Joshu asks OpenRouter not to send your content to model providers that may train on it, and the box image has many security updates.
